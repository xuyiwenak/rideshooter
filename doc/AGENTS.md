# 修改归档规则

作用范围：doc/。此目录保存 Markdown 开发记录，不存 Godot 缓存，也不复制整份源码。

## 命名

- 使用实际本地日期：YYYY-MM-DD，时区 Asia/Shanghai。
- 日期下按交付批次建 v001、v002……；每日重新从 v001 起，先查已有目录，绝不覆盖同名版本。
- 版本身份是完整的“日期/vNNN”；与 GAME_DESIGN.md 的文档版本或正式游戏发行版本无关。
- 每个版本至少包含 CHANGELOG.md，模板见 [_templates/CHANGELOG.md](_templates/CHANGELOG.md)。
- 同一任务尚未交付时可以补全自己的记录；交付后记录保留。后续更正另建版本并引用原记录，不悄悄改写历史。
- 不为过去对话倒推版本号；首次建立归档时以“当前基线”概括既有成果，区分本轮新增内容。

## 每次记录内容

日期、版本、状态、用户目标、变更摘要、涉及文件、行为变化、验证命令与结果、未完成/风险、下一步。没有运行测试就明确写未运行以及原因；人工试玩与自动测试分开。

## 收尾

1. 更新本目录 README.md 的最新版本指针和历史索引。
2. 目录或当前状态改变时同步根 README.md；架构职责变化时同步模块指引。
3. 检查 Markdown 相对链接和文件名确实存在。
4. 索引可以持续更新；历史版本记录不当作当前事实来源。
5. 只记录用户任务内的变更，不增加自动化任务，不自动 Git 提交。
